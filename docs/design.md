# 设计与实现取舍

## 研究问题

分段筛的教科书复杂度是固定的，但工程实现里有一些可切换的选择。本项目把其中三个做成运行参数，用同一份代码做受控对照：

1. 余数位图的模数 `m`：2 / 30 / 210；
2. 每段的字节数：16–128 KB；
3. 对未来段素数的处理方式：队列（bucket）或每段重新扫描。

## 余数位图

对模数 `m`，段内只保留满足 `gcd(r, m) = 1` 的余数 `r ∈ [1, m)`，每位一个候选数。段起点对齐到 `m` 的整数倍，于是段内第 `b` 块第 `j` 位对应的整数就是 `base + b*m + residues[j]`。

- `m = 2` → 1 bit/block，即经典的“只存奇数”位图；
- `m = 30` → 8 bits/block，跳过 22/30；
- `m = 210` → 48 bits/block，跳过 162/210。

`WheelTable::locate()` 把一个整数映射到它在位图中的位；`step()` 给出相邻互素余数之间的距离，用于推进 `k`。

## 标记过程

对每个筛素数 `p`（与 `m` 互素），只需标记 `x = k·p`，其中：

- `k ≥ p`：更小的因子已经由别的素数处理；
- `gcd(k, m) = 1`：否则 `x` 本身不在位图里（有 2/3/5/7 的小因子）。

因此 `k` 本身就沿着同一张轮表前进；这避免了逐整数检查 `x` 是否落在余数集合内。所有写位操作都是 `byte &= ~(1 << bit)`。

## 素数划分（队列模式）

段 0 时一次性把筛素数切成两段：

- `p² < high₀`：直接素数，每段从 `max(p², base)` 开始标记；
- 其余：跨段素数，入队到 `⌊p² / 段长⌋` 号段。

队列被消费时，从存档的 `k` 继续标记到当前段尾，再把新的 `k` 入队到下一个包含倍数的段。**划分必须固定**：如果让边界随段漂移，同一素数会同时被直接路径和队列路径标记，产生重复工作（开发中实测到标记数从 2856 万涨到 3352 万）。

队列关闭时，所有素数都走直接路径；两者标记集合相同，差异只在素数遍历与起点计算次数。

## 内存与时间

- 位图占用 `segment_bytes` 字节（由 `blocks × bits_per_block / 8` 决定），与 `limit` 无关；
- 筛素数表占用 `O(√n)`；
- 队列占用 `O(跨段素数数 × 在途段数)`。

## 与朴素实现的对照

`src/reference.cpp` 提供两个独立计数器：试除法和普通奇座位图。测试把三种轮宽 × 两种队列模式与试除法在小范围逐项比对，并在大范围对照已知 π(n) 值。任何配置不一致都会让 `ctest` 失败。
