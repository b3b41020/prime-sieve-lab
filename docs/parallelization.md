# 并行化与无竞态设计

## 问题

`src/sieve_core.cpp` 是串行分段筛；要把分段队列并行化，最大障碍是**轮次边界之间的竞态**：一个素数在本段产生的倍数要登记到「未来段」的队列里，而未来段可能正在被别的线程筛。

先明确竞态点（串行代码里对应 `sieve_core.cpp:104-109` 的 `buckets_.push` 和 `consume_bucket` 的 `buckets_.push`）：

```
段 S 的桶被消费 → 把素数 p 的下一个倍数登记到段 S+k 的桶
                      ↑ 如果段 S+k 正在被线程 B 筛，这里就发生对同一 vector 的并发写
```

## 结论：把「队列簿记」与「标记执行」拆到两个角色

并行实现（`src/sieve_parallel.cpp`）不是给串行版加锁，而是重构了职责边界：

| 角色 | 谁 | 干什么 | 会不会并发冲突 |
|------|-----|--------|----------------|
| **协调器** | 单个线程（tid==0，在 barrier 后运行） | 持有唯一的 `far` 队列；每段结束后为下一段生成**不可变的工作清单**（`Slice::jobs`） | 否——只有它碰 `far`，且在 barrier 的排他窗口内 |
| **工作线程** | T 个 | 只写**自己的位图字节切片**，只消费自己的 `jobs`；直接素数无状态重算 | 否——切片按块号划分，两两不相交 |

关键重构：**跨段素数不再由 worker 自己「推进并重新入队」**，而是协调器把每个素数在下一段要标记的**每一个具体倍数**（`MarkJob{prime, multiple}`）预先算好，塞进对应切片的 `jobs`。worker 拿到的是一条纯只读清单，做完就结束，不产生任何新的共享写。

## 无竞态的三条不变量

1. **空间隔离**：位图按「块范围」切成 T 份（`blocks * t / T .. blocks * (t+1) / T`），块号整除 `bits_per_block`，所以任意两个线程写入的字节区间不相交——不需要对位图加锁。

2. **时间隔离**：段是严格串行的（所有线程一起处理段 0、再段 1、…）。协调器在**两个 barrier 之间**独占运行：第一个 barrier 保证「所有人写完了当前段的位图与计数器」，第二个 barrier 保证「下一段的工作清单已经就绪」。因此 `far` 的读-改-写永远不会和任何 worker 的写重叠。

3. **层级规则**：只有满足 `2·p ≥ segNums`（即 p 在每段至多一个倍数）的素数才进 `far` 队列。这保证一个素数在段 S 产生的新登记，目标段 `S+k` **严格大于 S**——不可能写回正在被筛的段。小素数走「直接层」，由每个 worker 对自己的切片无状态重算，天然无共享。

> 规则 3 为什么是必要的：如果允许一个素数在段内有两个及以上倍数，它的「下一个倍数」可能仍落在**当前段**，于是协调器在准备下一段时就得写当前段——破坏了时间隔离。测试里的 `crossing_from` 是一个故意放低阈值的 hook，用来验证实现确实在规则被挑战时也能给出确定性结果（见下）。

## 正确性的可证判据：marks 与线程数无关

如果存在边界竞态，位清除操作会**重复或丢失**，导致总标记数随线程数漂移。因此 `tests/check_parallel.cpp` 断言：

- 并行计数 == 串行计数；
- **并行 marks == 串行 marks**，且对 t=1,2,3,4 完全一致；
- π(10⁹) 精确等于 50847534。

实测（`experiments/PARALLEL.csv`）每一项的 `marks` 列都与串行完全相同（313898259 / 3391186733），这是「无竞态」的直接证据，不是「结果碰巧对」。

## 加速比（实测）

| 上限 | 段 | 线程 | 耗时 (s) | 加速 |
|------|-----|------|---------:|-----:|
| 10⁹ | 32KB | 1 | 1.897 | 1.00× |
| 10⁹ | 32KB | 2 | 1.006 | 1.88× |
| 10⁹ | 32KB | 4 | 0.574 | 3.31× |
| 10⁹ | 32KB | 8 | 0.519 | 3.65× |
| 10⁹ | 64KB | 8 | 0.451 | 4.24× |
| 10¹⁰ | 32KB | 1 | 21.24 | 1.00× |
| 10¹⁰ | 32KB | 4 | 7.92 | 2.68× |
| 10¹⁰ | 32KB | 8 | 8.07 | 2.63× |

10⁹ 上 8 线程 3.65×（64KB 段时 4.24×），受协调器串行段（生成作业清单）+ 双 barrier 开销限制，未达理想 8×；10¹⁰ 上 8 线程相对 4 线程不再增长，瓶颈转向协调器作业生成与内存带宽。

## 代价与已知限制

- **协调器是串行热点**：每段要为下一段生成所有跨段倍数的作业，这是「不可变清单」方案换取确定性付出的成本。10¹⁰、8 线程时它已成为限制因素。
- **双 barrier**：每段两次全线程同步，段越小同步越频繁；段大小与线程数需联合调优（当前实现段内直接层重算，段太小时并行收益被同步吃掉）。
- **单机多线程**：未做跨机（MPI / 共享内存）切分；`limit` 的内存占用仍是 `O(segment_size)`，与串行一致。

一句话概括：**并行版通过「协调器单线程簿记 + 工作线程只读作业清单 + 块切片空间隔离 + 层级规则时间隔离」四重机制，把跨段队列的竞态从结构上消除，并用「marks 与线程数无关」这一可证判据在 CI 里持续守住。**
